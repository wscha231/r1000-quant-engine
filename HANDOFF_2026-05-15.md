Currently it only runs as a sidecar reading the Mode-Y-filtered book (= double filter). To get a clean macro-only headline, either (a) add a new `mode_macro_circuit_enabled` workflow input that puts macro inline in `build_operating_target_books.py` (parallel to Mode Y), or (b) reorder the workflow so macro runs before broker_replay.

2. **Mode Y on Main is questionable**. Iter 6 Main 18.44% / -31.93% is worse than Iter 5 Main 19.85% / -32.13% which was worse than Iter 2 23.10% / -29.98%. Mode Y main filter (bear=0.5, deep_bear=0.25) costs ~3pp CAGR with marginal MaxDD benefit. Consider passing `mode_y_main_multipliers=""` (empty) to disable Main filter while keeping Conc filter.

3. **Concentrated strategy metadata mismatch**. The engine emits historical Conc backtest with conviction_curve/N=2 (champion filter winner) AND latest recommendation with winner_take_all/N=3. F13 papers over this so the latest row passes the filter. A proper fix would either (a) re-emit Conc latest with conviction_curve/N=2 metadata, or (b) reconcile so engine emits one strategy. The mismatch suggests an unresolved architectural ambiguity.

4. **Survivorship hard gate flip**. F2 ships the tool; the gate flip awaits a real Tier-3 measurement that produces `outputs/audit/survivorship_coverage.json` with `hard_gate_flip_eligible: true` (coverage_ratio ≥ 0.85 AND delisted_count ≥ 100). 5. **CAGR target gap closure** would require structural changes:
   - Leverage (not currently in scope)

   - Higher-frequency rebalance (daily/weekly instead of monthly) — would require a much wider change to backtest_portfolio + data infrastructure
