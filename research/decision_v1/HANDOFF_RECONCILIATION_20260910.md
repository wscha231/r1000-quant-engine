## 실제로 고친 결함

기존 `compare_development`는 날짜·자료 종류·`costs_included=true`를 확인했지만
동일 비용·시장자료인지 비교하지 않았다. 실제 H1/quality 합성 재생으로 한쪽에
25bps, 다른 쪽에 5bps를 적용했을 때 저비용 실행이 선택되는 반례를 재현했다.
이를 alpha 개선으로 읽을 수 있는 경로였다.

이제 완료 결과에 `comparison_basis`와 해시를 저장한다. 공통 가격/거래량·FX·
금리·벤치마크·기업행사 전체 스트림, seed, 역사적 universe, macro, 후보 H1
가격/재무/선택 입력, 비용·현금·체결·ADV·미체결 정책이 같아야 비교할 수 있다.
정성/시나리오/위험 판단과 config의 차이는 전략 변경으로 남고 원래 결과와
설정 해시를 함께 출력한다. 보유 차이로 생기는 held-only export는 공통 후보
입력과 분리하되 각 실행 안에서는 계속 검증한다.

이전 결과에 공통 조건 해시만 사후 추가해서는 안 된다. 보존 입력으로 다시
실행해야 한다. 해시 일치는 원본 인증·진짜 과거 유니버스·독립 사전등록을
증명하지 않으며 source/OOS 인증을 자동 해제하지 않는다.

손익은 `현지 자산 손익 + 환율 환산 손익 - 실제 비용 = 순 손익`으로 대사한다.
환율 변화는 직전 보유수량과 배당 미수금에 먼저 적용하고, 현지 가격 변화에는
새 환율을 사용한다. 가격/환율 교차항은 현지 자산 손익에 포함한다. 이 항목은
배당과 기업행사 회수도 포함하므로 순수 주가 효과라고 부르지 않는다. 실제
수수료를 더해 본 값을 별도의 무비용 전략 수익률로 부르지도 않는다.
현금이자는 기존 0% 가정이며 바꾸지 않았다.

## 검증

고정 환경: `requirements_research_decision_v1.txt`에 맞춘 Python 3.12 환경.
이번 검사는 합성 자료이며 실제 투자성과는 계산하지 않는다.

```sh
python tools/run_pr_validation.py --only research_fund_replay_smoke \
  --only research_workflow_funding_smoke --only research_workflow_quality_smoke \
  --only research_decision_v1_decision_smoke --quiet
python -O tests/research_fund_replay_smoke.py
```

실제 결과: 등록된 네 suite 모두 통과(exit 0, 27.80초). fund 31개와 기존
funding 14·quality 연결 24·H2 decision 46을 검사했다. fund 31개는 `-O`에서도
통과(exit 0, 12.10초)했다. 내부 중복 호출 때문에 이 수를 고유 총수로 합산하지
않는다. 처음 runner 호출은 `--only`를 반복하지 않아 argparse exit 2였고,
위의 정확한 호출로 수정했다. 이미 등록된 fund suite를 확장했으며 보호된
등록 pin이나 검증 알고리즘은 변경하지 않았다.

회귀는 다른 비용/가격/벤치마크/매크로/universe/ADV 실행의 비교 차단,
같은 공통 관측에서 정성 판단 변경의 비교 허용, 구형·변조된 비교 근거 차단,
KRW 환율과 미수 배당·환전비용의 손익 대사를 포함한다. 원래 실행기를 통한
커밋 소스 재생·원격 게시 결과는 PR의 정확한 소스/실행 기록과 연결한다.
