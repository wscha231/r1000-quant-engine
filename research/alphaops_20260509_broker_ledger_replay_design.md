# Broker Ledger Replay Design

Date: 2026-05-09
Status: design draft
Purpose: define the internal execution-grade replay layer that converts r1000 target portfolios into account-like trades, shares, cash, and equity curves.

## Problem

Current production backtests are weight-level portfolio simulations. They are useful for strategy research because they carry `current_w`, drift weights by returns, apply monthly turnover cost, and move exited positions to CASH. However, the latest portfolio files such as `portfolio_latest.csv` and `concentrated_portfolio_latest.csv` are target-weight recommendations, not a broker ledger.

The user wants a replay that answers:

- If the account started with USD 100,000 in 2019, what did it buy?
- How many shares were held after each trade?
- How much residual cash remained after integer share purchases?
- Which orders were generated by monthly rebalance, stale-leader trim, hard stop, relative underperformance, macro defense, or monster promotion?
- What CAGR, MaxDD, Sharpe, turnover, and trade history result from actual end-of-day fills?

## Scope

This layer must not replace the alpha engine. It should sit under the existing selection stack.

Inputs:

- `outputs/reports/main_monthly_weights.csv`
- `outputs/reports/concentrated_strategy_holdings.csv`
- `outputs/reports/concentrated_strategy_monthly.csv`
- optional future `*_weekly_targets.csv`
- daily price cache from `cache_prices/`
- cost settings from `EngineConfig`
- optional risk-action sidecars

Outputs:

- `outputs/broker_replay/main/metrics.json`
- `outputs/broker_replay/main/equity_curve.csv`
- `outputs/broker_replay/main/trades.csv`
- `outputs/broker_replay/main/holdings_daily.csv`
- `outputs/broker_replay/main/holdings_weekly.csv`
- `outputs/broker_replay/main/cash_ledger.csv`
- `outputs/broker_replay/main/target_vs_actual_weights.csv`
- equivalent files for `concentrated`

## Core Objects

### TargetBook

One row per intended target holding.

Required fields:

- `decision_date`
- `effective_trade_date`
- `portfolio_kind`
- `ticker`
- `target_weight`
- `target_notional`
- `sleeve`
- `reason`
- `source_file`
- `run_id`

Rules:

- For main, use `main_monthly_weights.csv`.
- For concentrated, filter to the chosen champion only before replaying. Never replay the full concentrated experiment grid.
- Weight sum must be <= 105%. Otherwise block the replay.
- CASH rows are allowed, but missing CASH is interpreted as zero target cash, not as proof that no residual cash will exist.

### BrokerState

Mutable account state after each mark-to-market date.

Fields:

- `cash_usd`
- `shares_by_ticker`
- `cost_basis_by_ticker`
- `last_price_by_ticker`
- `realized_pnl_by_ticker`
- `unrealized_pnl_by_ticker`
- `equity_usd`

### OrderIntent

Generated from target weights versus current holdings.

Fields:

- `decision_date`
- `fill_date`
- `ticker`
- `side`
- `target_weight`
- `current_weight`
- `target_notional`
- `current_notional`
- `trade_notional`
- `reason`
- `source_target_id`

Rules:

- Ignore tiny trades under a configurable notional threshold.
- Optional integer-share mode floors buy quantities and leaves residual cash.
- Optional fractional-share mode is allowed for research, but production-style metrics should default to integer shares.

### Fill

Executed order row.

Fields:

- `fill_date`
- `ticker`
- `side`
- `quantity`
- `fill_price`
- `gross_value`
- `fee_usd`
- `slippage_usd`
- `net_cash_delta`
- `cash_after`
- `shares_after`

## Timing Rules

No lookahead is more important than flattering CAGR.

Default conservative timing:

- Signals dated `T` are known after the close of `T`.
- Fill at the next available trading day's close by default.
- If no fillable price appears within 7 calendar days, skip that fill rather than backdating sparse-history prices.
- A second sensitivity mode may fill at next open.
- Same-day close fills are research-only unless the signal can be proven to exist before the close.

Risk exits:

- If a daily close triggers a stop, the default fill is next trading day close.
- Same-day close stop fills are not production-valid because they use the closing price to decide and fill simultaneously.

## Simulation Loop

For each trading day:

1. Mark all current positions to market.
2. If the day has target portfolio changes, generate order intents.
3. If the day has risk actions, merge them with target intents by priority.
4. Resolve conflicts:
   - hard stop sell beats new buy
   - stale-leader exit beats ordinary hold
   - monster promotion can override ordinary cap only if the target book says so
   - macro defense can raise cash, but confirmed monster exceptions may remain
5. Execute fills at configured close/open price.
6. Update shares, cash, cost basis, realized PnL.
7. Emit daily account snapshot.

## Conflict Priority

Highest to lowest:

1. Data validity block
2. Hard stop / delisting / missing price forced block
3. Confirmed distribution exit
4. Macro crisis cash ladder
5. Stale leader half-trim or exit
6. Monthly/weekly target rebalance
7. Monster staged add
8. Residual cash deployment

## Metrics

Primary metrics must come from account equity, not target weights:

- CAGR
- total return
- MaxDD
- Sharpe
- Sortino
- monthly and annual turnover
- fee drag
- slippage drag
- average cash
- average residual cash
- max single-name actual weight
- trade count
- win/loss by realized round trip

Broker replay metrics should become the highest-trust promotion gate.

## Main Replay

Initial version:

- monthly targets from `main_monthly_weights.csv`
- integer shares enabled
- fill at next close
- 25 bps per side cost
- no leverage
- no shorts
- daily mark-to-market

Research toggles:

- fractional shares
- next open fill
- no small-trade threshold
- weekly risk exits enabled
- macro cash ladder enabled

## Concentrated Replay

Initial version:

- filter concentrated holdings to the champion configuration only:
  - `target_stock_names == 3`
  - `weighting_mode == score_power`
  - `active_rebalance_interval_months == 1`
- block if monthly target weight sum exceeds 105%.
- allow max single-name target up to 50% only when the target book explicitly requests it.

Do not replay the full experiment grid as if it were one portfolio.

## Validation Tests

Required tests:

- one-stock buy-and-hold grows by the adjusted close return.
- integer share mode leaves residual cash.
- fractional mode can reach target weights exactly.
- same-day-close fill mode is marked research-only.
- next-close mode does not use future data before signal date.
- duplicate target rows are aggregated or rejected explicitly.
- concentrated experiment-grid contamination is blocked.
- trade fees reduce equity by the expected amount.
- no negative cash unless leverage mode is explicitly enabled.

## Workflow Integration

Run order after full rebuild:

1. full pipeline creates target books.
2. weekly freshness audit runs.
3. broker ledger replay runs for main and concentrated.
4. goal search reads broker replay metrics first.
5. monthly weight-level metrics remain available as lower-trust research diagnostics.

Artifacts:

- include `outputs/broker_replay/**` in GitHub artifact zip.
- sync branch-isolated `outputs/broker_replay/**` to Google Drive.

## Promotion Rule

Production promotion must require:

- broker replay completed.
- metric mode is `broker_ledger_next_close`.
- no invalid target books.
- no stale final evaluation beyond threshold.
- no non-finite metrics.
- no contaminated concentrated grid.
- cost bps sensitivity passes.

Weight-level monthly metrics can suggest candidates, but cannot be the final production gate.
