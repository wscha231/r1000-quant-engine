# Update Log v2026.04.10.1

Date range: 2026-04-09 to 2026-04-10

## Files changed

- `colab_run.ipynb`
- `r1000_top30_institutional.py`

## 2026-04-09

### Colab SEC bulk updater

- Added an optional Colab cell that downloads `companyfacts.zip` directly from the SEC bulk archive endpoint.
- Download flow now uses a SEC-compatible `User-Agent`, retry/backoff, temp file replacement, ZIP integrity checks, and a minimum size guard before replacing the existing file.
- Download target is Google Drive project storage: `/content/drive/MyDrive/r1000_top30_institutional/companyfacts.zip`.

### Companyfacts refresh cadence

- Changed the automatic refresh threshold from 7 days to 3 days in the Colab updater cell.
- Goal: keep SEC fundamentals fresher without forcing a download every run.

## 2026-04-10

### Portfolio sleeve promotion logic

- Added promotion logic so names initially classified as `early_scout` can be upgraded to `future_winner` when they already show stronger confirmation.
- Promotion now considers:
  - fundamental confirmation
  - market confirmation
  - historical statement depth
  - benchmark relative strength
  - Minervini momentum state
  - breakout setup quality

### Entry cap vs drift cap separation

- Reworked sleeve-specific name caps to distinguish:
  - new entry cap
  - drift cap for already-held winners
  - hard absolute risk cap
- This is now handled separately for `future_winner` and `early_scout`.
- Purpose: do not force-sell winners too early, while still limiting new speculative entries.

### Backtest drift behavior

- Updated monthly backtest state handling so held positions drift with realized monthly returns between rebalances.
- This makes the next rebalance use a more realistic previous weight map instead of a stale target-only weight snapshot.

### Diagnostics exported to latest outputs

- Added export visibility for new sleeve-debug fields, including:
  - `portfolio_sleeve_label_raw`
  - `portfolio_sleeve_promotion_signal`
  - `portfolio_sleeve_promoted`
  - `portfolio_prev_weight`
  - `portfolio_existing_holding`
  - `portfolio_name_cap`

### Follow-up fix after review

- Fixed a bug where `future_winner` drift caps could bypass stricter existing caps already applied to the same name.
- The drift allowance is now bounded by the active effective cap instead of overriding it.

## Expected effect

- Better separation between speculative entries and winners that have already proven themselves.
- Less premature trimming of strong names.
- More realistic portfolio weight evolution in backtests.
- Easier CSV-based diagnosis of why a name stayed `early_scout`, was promoted, or received a specific cap.
