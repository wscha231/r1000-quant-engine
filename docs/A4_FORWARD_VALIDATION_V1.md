# Independent A4 fixed-forecast validation

`tools/a4_forward_validation.py` adds three offline commands. It changes no
collector, scheduler, Source implementation, learner, portfolio or accepted
state. Full JSON stays in a private directory; stdout contains status and
file/hash/size metadata only. Empty forecasts never count as a completed
predictive system. A3 and A5 are not imported or executed by this component.

## Inspect the original current report

`inspect --report <original.json> --report-sha256 <original-file-sha256>
--output-dir <private-directory>` checks the original bytes, report content
hash, completed NYSE session, report expiry and required/enhanced readiness.
It reports diagnosis readiness separately from fixed forecasts and standalone
operation. It is an inspection of externally pinned report bytes, not a replay
or authentication of the Source operands. It cannot certify scheduled
execution, data rights, historical price clocks or completion of the whole
workflow. An expired report stays blocked even on a weekend with no new close.
Blocked readiness exits with status 2 after saving its private diagnostic;
successful command execution cannot conceal an expired diagnosis.

## Record before the next-close entry

`record --input <forecast-input.json> --input-sha256 <file-sha256>
--protocol <protocol.json> --protocol-sha256 <file-sha256>
--output-dir <private-directory>` accepts no prices or actual outcomes.
There is deliberately no CLI recording-time override. Recording must occur
after the decision close and strictly before the next NYSE close, including
holidays and half-days. Duplicate feature/target/horizon/outcome predictions,
late creations, unknown fields and invalid values are refused.
Estimates and contributions must be finite JSON numbers; numeric strings and
booleans are refused before any record/reference is written.

The externally pinned protocol is not generated or approved by this tool. Its
closed schema is `a4-forward-validation-protocol-v1`, purpose
`FIXED_FORECAST_RESEARCH_ONLY`, with `available_at`, `expires_at`, the unchanged
14-target list, seven registered horizons and three outcomes from the learner.
`embargo_contract` must equal
`PRESERVE_ORIGIN_FAMILY_NOT_CHANGED_BY_SCORING`. This tool does no fitting or
resplitting and cannot relax an origin family's 126/252-session embargo.

The input's closed schema is `a4-forward-record-input-v1`: `decision_session`,
`report_sha256`, `trial_sha256`, `release_policy_sha256` and `predictions`.
Predictions retain the exact original `forecast_release` fields. Their
feature/family, decision and reviewed-trial reference must agree. Empty inputs
require null trial/release-policy references and emit `NO_FIXED_FORECASTS`.
These origin hashes are references, not a replay or independent qualification
of that trial/release. The original Source and forecast-release gates remain
necessary before using a forecast in A4/A3/A5.

Output names are their immutable file SHA256. Identical writes are reusable;
conflicting bytes and symlinks refuse. The record includes a canonical protocol
content hash independently from the CLI's original protocol file hash. Original
recording/scoring implementation and direct mathematics hashes are retained.
Changed implementation refuses old records rather than silently redefining
their errors; a separately reviewed migration or original-version replay is
required. None is generated by this tool.

The record command commits its data object before a small hash-addressed
`record-references` receipt in the same private output directory. The same
input/protocol reuses that first record and original clock, including recovery
after entry or protocol expiry; it does not create another prediction. A
corrupt/missing referenced object blocks. An interrupted object without its
reference is not silently accepted after entry. This local recovery index is
not a canonical experiment ledger, model head or durable publication proof.

## Score after outcome maturity

`score --record <record.json> --record-sha256 <file-sha256>
--protocol-content-sha256 <record.protocol_sha256>
--learning-input-root <original-learning-bundle>
--learning-policy-sha256 <original-policy-file-sha256>
--output-dir <private-directory>` is a separate process and accepts the
existing original-bound `learning_request.json` contract. Original hashes,
rights/purpose bindings and the externally pinned learning policy are checked
through `load_learning` and `validate_inputs`; no fit or substitute policy is
created. Price availability must not exceed the declared input cutoff.

The existing `score_predictions` verifies the next-close path and realized
return, drawdown or volatility. A prediction remains pending until its full
horizon matures. A matured but incomplete path is reported separately. Errors
are compared with the original frozen training-mean baseline
`estimate - contribution_vs_training_mean`. All 14 targets and seven horizons
remain visible, including missing forecasts. Feature votes and overlapping
outcomes are never counted as independent observations or aggregated into a
new investment forecast. Direction correctness uses three-way return signs,
including exact zero; a flat realized return is not a successful down call.
Coverage remains `INSUFFICIENT_EVIDENCE`; a single
scored record does not qualify a model or establish incremental performance.
Protocol expiry is enforced at recording, while the learning policy must be
valid at scoring. An old properly recorded forecast does not expire merely
because its original protocol has since expired.

## Evidence limits and operations

A local clock and hash do not prove independent publication time or that a
human has never seen historical outcomes. `independently_timestamped`,
`human_blindness_certified`, `validated_backtest`, Source/PIT admission and
selector/portfolio effects remain false. No old historical outcome becomes a
fresh holdout. Independent pre-entry durable publication and an approved
separate evaluator are still required for a qualified forward experiment.
This component does not create a second canonical experiment ledger.

CLI failures retain bounded private diagnostic records when the output path
is usable; stdout never includes raw input bodies or exception paths. A failed
prerequisite produces no successful record or score. Existing private Drive
copy/check and approved original experiment-ledger indexing remain separate
operator responsibilities. Do not enable a new scheduler or publish numerical
records as public GitHub artifacts to test this component.

`forecasts_checked` includes pending/missing observations. `forecasts_scored`
counts only matured actuals with an error; an immature forecast is never
reported as a completed score. Implementation pins include the direct shared
number/UTC helper, not only the model and outcome mathematics.
The directly used JSON/clock and original-input loader implementations are
also pinned. The scoring CLI verifies its fixed record before opening learning
inputs, then repeats the record check with the scoring-time policy checks.
