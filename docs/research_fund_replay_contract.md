# USD chronological fund replay — v1

User requirement, 2026-09-10: start once with USD 100,000; select, buy, sell and
adjust cash using information available at each historical decision; evaluate
through the specified last completed close; prioritize after-cost CAGR.

This is an executable research path dependent on the current H1/H2/quality
stack in PR #405. It is not an accepted account, broker connection, promotion,
historical data acquisition pipeline, or claim of a completed eight-year study.

## Invocation and source identity

```sh
python -I tools/run_research_decision_v1.py \
  --fund-input /data/fund_manifest.json \
  --config docs/research_fund_replay_config.json
```

Use the pinned `requirements_research_decision_v1.txt` environment. The existing
CLI first verifies committed source bytes, then executes that retained snapshot
under isolated interpreter paths. Dirty/untracked package code blocks execution.
The new mode cannot be mixed with one-shot `--market-export`, `--context`,
`--previous`, or `--quality-bundle` arguments. It writes only beneath
`outputs/research_decision_v1/`; exit 2 and null metrics mean blocked.

Event files are streamed one bounded JSON shard at a time (32 MB per input).
Each decision is archived separately, with its original validated packet. The
simulator retains only the previous full decision and compact historical
summaries. The immutable input archive preserves relative paths so its
`inputs/fund_manifest.json` can be replayed with the archived decision config.
All input references contain a relative `path` and the **canonical JSON SHA256**
in `sha256`; this differs from the hash of a whitespace-formatted file.

## Manifest

The canonical manifest has these fields (a concrete synthetic example can be
generated by `tests/research_fund_replay_smoke.fixture`):

| Field | Required interpretation |
|---|---|
| `schema_version` | `fund-manager-replay-v1` |
| `data_kind` | `REAL` or `SYNTHETIC`, never mixed |
| `evaluation_scope` | `FULL_7_8_YEAR` or `MECHANICAL_PILOT` |
| `start_at`, `end_date` | Explicit initial account timestamp and final close date; 2026-09-09 for this request |
| `base_currency`, `initial_cash_usd` | `USD`, exactly `100000` once, no external deposits |
| `markets` | Unique nonempty subset of `US`, `KR` |
| `decision_config_hash` | Canonical hash of the exact decision config |
| `selection_objective` | `after_cost_usd_cagr` |
| `fill_mode`, `cash_carry_mode` | `next_close`, `none` |
| `cost_bps` | Per-side execution friction by market; default 25 bps, including the assumed fee/spread/slippage burden |
| `fx_conversion_bps` | Additional KRW/USD conversion cost, declared explicitly (default example 0) |
| `max_pending_sessions` | Integer 1–20, fixed before replay |
| `opening_risk_free` | Published and observed annual-rate evidence available at inception |
| `benchmark_weights` | Fixed nonnegative initial weights across included markets summing to one |
| `evidence_mode` | `CONTEMPORANEOUS_RECORDS` or `RETROSPECTIVE_RECONSTRUCTION` |
| `seed_closes` | Latest completed exchange closes before inception, one per market, chronological; no corporate actions |
| `event_shards` | Ordered references to chronological event arrays |
| `decision_schedule` | Full study: `{"mode":"DAILY_AFTER_LAST_CLOSE"}`; pilot may use `{"mode":"EXPLICIT_FROZEN","times":[...]}` |

A full study requires REAL inputs and an elapsed span of 7–8.1 years (the small
allowance accommodates the chosen adjacent exchange sessions). Its decision
clock is five minutes after the last included market closes on each union
trading date. Omitting a difficult day is an error, not an implicit HOLD.
Every scheduled exchange close must be present. Warm-up financial and 20/60/
120/240-session RS history live in each H1 packet and do not earn returns
before inception. A shorter complete test retains the `MECHANICAL_PILOT` label.

## Market and decision events

Close event fields: `type=close`, `time` (official exchange close UTC), `market`,
`session`, `source`, `available_at`, `price_basis=raw_unadjusted`,
`corporate_actions_through`, `corporate_actions`, `fx`, `risk_free`,
`benchmark_total_return_index`, and `quotes`. Each quote provides `security_id`,
`close`, `volume`, and boolean `tradable`. Every held or pending name needs that
session's price, including an explicit mark for a halted name. A closed other
market retains its last local close while its USD value changes with FX.

Scalar evidence (`fx`, `risk_free`, each macro observation) contains `source`,
`value`, `payload_hash=digest(value)`, `published_at`, `observed_at`. Publication
must precede observation and observation must precede use. FX is KRW per USD,
positive and no more than 24 hours old at a market close.
An entirely US/USD fund does not require an unrelated KRW FX feed. Macro records
name `series` and carry `vintage_at=published_at`. A matching date/hash is a
consistency check, not remote document authentication or proof of first-release
economic data. The macro/regime producer remains responsible for the archived
release vintage and the stated rationale; this adapter does not invent a new
macro classifier or estimate future revised data.

Decision event: `type=decision`, `time`, `packet={path,sha256}`. Its packet has:

- `decision_cutoff`, `data_kind`, `market_exports` (original H1 outputs with
  retained raw input snapshots), and an explicit `quality_bundle`.
- `macro` and `context`; `context.regime.input_hash` must equal `digest(macro)`.
  Existing context FX scenario/risk constraints remain in force.
- `universe={source,public_available_at,members,members_hash}`. Members are the
  historical investable IDs. Exports must contain exactly those members plus
  still-held names, preserving risk and exit evidence for removed members.

H1 admission is recomputed. Its financial publication/first-seen/ingestion
times, price/corporate-action basis and exchange clocks are not overridden.
Admitted decision prices and latest share volumes must equal the simulator's available raw marks.
Current collection cannot be backdated into historical H1/quality admission.
All selected/held evidence must support a ready proposal. A reviewed negative
quality verdict can exclude or exit; unreviewed input blocks performance.

Input role boundaries stay explicit: macro regime sets the investment budget;
financial/scenario/price data drive valuation; reviewed business evidence
controls eligibility and exits; historical RS remains discovery information in
the existing engine. This change does not add an unvalidated fixed RS/13F/Form4
alpha weight or reuse a rejected portfolio rule.

## Actual simulated account and execution

- USD cash and actual share quantities, after earlier fills, create the next
  EXISTING_BOOK_PROPOSAL context. User-supplied account amounts are not treated
  as simulated state. The dollar balance is never reset at rebalance.
- USD-native returns have no KRW FX adjustment. KRW-asset USD scenarios use
  `spot / future_KRW_per_USD`; KRW reports retain the reciprocal convention.
  `_base` fields and the report currency prevent USD amounts being labelled KRW.
- Fixed orders are sized from prices known at decision time. HOLD preserves
  quantity. Subsequent raw exchange closes execute pending orders; a decision
  cannot receive a fill at the same close or consume a later market's proceeds.
- Sells at the same close may fund buys at that close. This is an explicit
  netting assumption; settlement delays, borrow, margin, tax lots and personal
  income taxes are not modeled. No negative cash or external funding is allowed.
- Buy gaps scale affordable whole-share purchases. Prior H1 ADV limits order
  capacity; actual session volume only caps achievable fills. Halts, partial
  fills and expiry are logged. At each new decision, explicitly cancel the
  unfilled remainder and reevaluate the actual filled book. An old pending BUY
  cannot suppress fresh risk/quality exits. Post-fill price drift can breach a
  target exposure; the next decision enforces reductions, not a hindsight fill.
- The new frozen config opts into risk-cap reductions and reviewed quality,
  membership and hold-hurdle exits before HOLD preservation. Old one-shot
  behavior remains the default. The existing scenario stress limit is not a
  guarantee that realized MDD stays within that percentage.
- `SPLIT` adjusts shares and pending quantity. Fractional reverse-split rights
  require explicit cash-in-lieu price/payment evidence. `DIVIDEND` creates an
  ex-date receivable, paid later. `CASH_DELIST` cancels orders and realizes cash
  recovery or zero recovery; a delisted ID cannot reenter. Actions must have the
  current session as their effective date. Unsupported stock mergers/spinoffs
  fail closed and require a separate lifecycle extension.
- Unpaid rights count in NAV but are excluded from spendable sizing capital.
  KRW cash flows are converted at the next processed mark/payment observation
  under the declared cost assumption. No FX forecast is used in realized NAV.
- On the final date, value remaining shares and rights plus cash; retain
  pending orders beyond cutoff. Do not force liquidation or invent final fills.

## Metrics, CAGR selection and remaining gates

The initial pre-trade USD100k row participates in all return and drawdown
calculations. CAGR uses actual elapsed seconds / 365.25 days; MDD includes the
first trading loss. Sharpe uses arithmetic daily returns less the risk-free
return accrued from already observed rates, with sample standard deviation.
Annualization uses actual observations per elapsed year for the union calendar.
Cash itself earns zero under the explicitly frozen control assumption.

Outputs include ending NAV, CAGR, MDD/recovery, Sharpe, Sortino, Calmar,
volatility, annual/monthly/rolling 12m and 36m performance, USD total-return
benchmark comparison, tracking error, transactions/costs, daily cash/holdings,
and per-security P&L that reconciles exactly to NAV less initial capital.

Development selection is executable through the same `--fund-input` option
with schema `fund-cagr-development-v1`, `trials=[{trial_id,result:{path,sha256}}]`,
`registered_trial_ids`, `development_end`, `test_start`, `max_drawdown`, and
optional `pbo_blocks`. All curves must use the same development timestamps and
end before the test period. Risk-ineligible trials remain visible. Among
eligible trials, CAGR is first, MDD breaks an exact tie, and ID is deterministic;
Sharpe cannot displace a higher CAGR. CSCV/PBO also selects and ranks by compound
growth, not by Sharpe or compounded arithmetic excess returns.

The older Run287 multiple-testing promotion contract is frozen historical
evidence and remains unchanged. The new comparison does not grant promotion:
Git-anchored preregistration, complete failed-trial history, DSR/WRC, source
verification and a genuinely unused test period are still separate obligations.
An already inspected historical period is not made unused by naming it OOS.
No 7–8 year real-data performance has been produced by these code tests.
