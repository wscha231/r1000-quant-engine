# Closed RTDSM macro extension candidate

The extension sources are PCPIX (core CPI, SA index), IPT (total industrial
production, SA index with vintage-specific base) and CUT (total capacity utilization, SA
percentage points). Monthly observations and monthly vintages remain distinct.
The complete visible vintage supplies each state; no revised-current series,
older-column fill, exact announcement clock or historical PIT is manufactured.
IPT and CUT share the G17 dependency group and are not independent votes.

The new tools/a4_rtdsm_extension.py keeps the original a4_rtdsm_sources.py and
primary codec bytes intact. It reuses their bounded XML/cell helpers, checks
all loaded code pins and records its own schema/normalizer hash. It accepts
IPT headers from1962:M11 without changing the old three-feed decoder. Existing
EMPLOY, PCPI and RUC generations were re-read and fully replayed from Drive:
18,816 observations /3,989,093 object bytes; no provider request or Drive write.
The exact receipt and the source rights-notice object remain separate evidence.

The existing collector gains only an explicit isolated CLI mode. Defaults,
legacy feed registry, scheduler, workflow flags, current-risk operands and all
native learning/trading gates stay unchanged. A pinned closed recipe selects
all three fixed source URLs and exact local method/rights objects. A completed
HTTP body is retained before normalization together with request-start and
body-completion references. Redirects, credentials, arbitrary URLs and provider
retries are unavailable. Failure stops the batch and preserves returned bytes.
An explicit fresh attempt may reuse exact previously replayed generation pins;
no old-success fallback or timestamp refresh occurs.

Publication reuses the existing objects/generations/executions namespace and
transport. All objects precede manifests, and execution is last and reread.
The separate data-center typed view also requires an exact successful component
execution receipt containing the generation. Failed batches and readback
witnesses refuse that route. The existing combined8-vintage-reference,
64MiB-read and150,000-row budgets include old and new inputs together. The
extension is not inserted into the price/financial Reader or current risk list.

Per-workbook limits remain8MiB raw,64MiB expanded XML,1,000,000 cells and24
retained months per vintage. A32MiB normalized decoded ceiling is explicit.
The first recipe proposes2015:M1 through2026:M10; actual coverage is unknown
until original capture and replay. Its three workbooks are not yet collected.
The HTTP stream checks a180-second capture budget and a30-second socket bound;
this is not a hard whole-process bound. The execution packet must separately
bind the existing supervised CLI/owned-process timeout, including durable
transport and partial/timeout recovery, before a real attempt.

Method documents and the Philadelphia Fed research-use notice are original
review material, not a supplier-wide ML grant. All Source/PIT/training/model/
portfolio authority remains false. No new fit, after-cost backtest, current
forecast or A3/A5 invocation is part of this Source extension. The registered extension and existing primary/data-center/legacy-vintage
proofs are included in the existing PR runner and A6 dependency inventory.
Registration does not authorize a Source execution or a native model.

The successful component receipt binds three unique generation hashes to the
ordered three feed captures. The recipe is retained as a hash-named original
object, published before successful generation publication and reread by the
typed view. Its window, rights and normalizer dependencies must match each
selected generation. Reuse flags and transport verification cannot disagree
with the capture map or publication status. The earlier r1 preparation
counterexample is retained; no actual Source capture used that draft.

Offline original replay with a supplied collection clock stays supported.
The typed collection-verified route additionally requires the replayed
capture_ref and BODY_COMPLETION_CALLER_REFERENCE precision. A successful
execution bound to a valid offline generation cannot supply that evidence.
The recipe collector pin must match this reader's trusted loaded producer
bytes, which are checked again before extension replay. A different collector
revision needs an independently reviewed compatible reader or migration;
syntactically valid caller-rebound hashes do not establish producer evidence.

The data-center CLI pairs repeated --extension-vintage-generation-sha256
and --extension-vintage-execution-sha256 values. An optional
--extension-vintage-archive-root selects an existing local archive; otherwise
the existing approved Drive transport is used. Each selected generation
requires the exact successful component execution and retained recipe object.
The existing default workflows do not automatically enable this isolated mode.
