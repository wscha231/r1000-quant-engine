## Native review-boundary corrections - 2026-10-05

Generic code, config, model, parameter or dependency identity changes and an
unscoped exposure-index change invalidate every current candidate's earnings,
cashflow, valuation, ER, RS/timing, risk/thesis, competitive-position and
filing/content-extraction review slices. These identities do not prove a narrow
affected scope. Ordinary PRICE events remain selective. The full invalidation
is an A2/A3 review suggestion; it performs no financial extraction or valuation
and grants no A0, Registry, ER or A5 execution authority.

An SEC accession's first ten digits identify the submitting entity, which may
be a third-party filing agent, rather than necessarily the issuer. The adapter
therefore retains the raw SHA, top-level issuer CIK and selected recent-accession
checks without requiring accession-prefix equality. See the official
[SEC accession explanation](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data)
and [Netskope issuer 2063196 / accession 0001193125-26-255439](https://www.sec.gov/Archives/edgar/data/2063196/000119312526255439/0001193125-26-255439-index.htm).
The regression uses that published pair with separately constructed metadata
and clocks; it is not authenticated submissions, earnings extraction or PIT.
Accepted event time, source observation, availability and collection remain
distinct, with no fabricated publication timestamp.

Eleven additional boundary methods preserve the original 341 case bodies:
352 new native methods and 468 including the unchanged 116-case H1 baseline.

# Candidate reassessment bridge V1

TASK_KEY: R1000-H1-EVENT-REASSESSMENT-BRIDGE-V1-20261004
Scope: pure source-change/impact/review parameter preparation; no new model, scheduler, store or financial mutation.

## Contract

`calendar_rows` invokes the exact existing Calendar C1 `build_h1_batch`, including the unchanged H1 persisted validator. It preserves identity nulls, H1 availability and publication precision. A provider publication later than the decision cutoff cannot become earlier knowledge. Both estimates missing is MISSING, not OBSERVED. Provider lookback fields remain provider observations, not historical revisions.

`macro_rows_from_context` calls the existing Chameleon `verify_context` and emits individual logical-series observations. It never interprets a market-only series as an automatic company exposure. Its observed_at is the actual time this adapter sees the context, not a backdated series publication timestamp.

`snapshot` requires one explicit COMPLETE comparison scope. Partial-batch snapshots must have distinct fixed scope_id values. Removing an observation from a complete scope invalidates its previous use; it is not HOLD or zero. A target-period roll/provider/basis change is not a same-identity estimate revision. New macro observation dates trigger review even at the same value. Repeated daily consensus responses with the same target-period data do not trigger merely because collection day advanced. This last rule does not create retrospective PIT.

`exposure_index` retains all supplied candidates, including WATCH/REJECT/BLOCKED/NOT_SELECTED. Its SECURITY/ISSUER mapping and macro/theme edges must be provided by the native identity/source-graph owner. Evidence hashes and timestamps are checked structurally, not independently authenticated. No new numeric transmission coefficient is inferred. The index expiry is explicit; an expired index cannot certify impact completeness.

`plan_reassessment` handles observed-value changes, new periods, corrections, missing/stale/failure, scope disappearance, expiry, explicit catalyst/hard-risk/outcome due events and changed source/config/model/parameter/dependency identity. Unknown previous identity prevents NO_NEW_REVIEW_INTENT. Same-time conflicting values and backward collection clocks are rejected. Unmapped events remain visible and request mapping/discovery; candidates are not silently removed.

The output has per-asset invalidation suggestions and at most one aggregate intent per A0 agent. It is NOT the native `task-packet-v2`, `system-state-v2`, `completed_tasks` receipt, current Registry or approved decision. `NO_NEW_REVIEW_INTENT` is only semantic triage; only native A0 verified receipts may authorize SKIP_UNCHANGED.

## Refresh semantics

- ACTUAL/GUIDANCE/CONSENSUS -> affected A1/A2 and A3 earnings/cashflow/valuation/ER REVIEW. ACTUAL adds full earnings-thesis review.
- PRICE/LEADERSHIP -> RS/timing/current valuation/ER REVIEW, not full company research.
- MACRO -> A4 global context; A3 cashflow/valuation review only for explicitly linked transmission channels. A4-to-A5 common risk review may be needed even without company exposure mapping.
- REGIME -> risk/timing overlay; it does not rewrite company cashflows by itself.
- OPTIONS/SENTIMENT/POSITIONING -> risk/timing context; not intrinsic-value bonus or independent votes.
- Missing/stale/failure -> A1/A6 repair and invalidation. No fresh economic conclusion is proposed from failed data.
- HARD_RISK_REVIEW -> existing P0 verification route; do not wait on unrelated RS freshness. The bridge does not authenticate the risk allegation or authorize liquidation.
- OUTCOME_MATURED -> A8 only after explicit due time. The actual labels/source still need native verification.

Multiple contemporaneous events aggregate asset IDs and slices into one intent per agent. Causal event IDs are retained for downstream dedupe but NOT asserted or scored by this bridge. There is no event scheduler, debounce clock, acknowledgment store or execution queue here; existing A0 owns those boundaries.

## Limits / completion

The new module executes without network or filesystem writes. Test runners and example scripts write only their scratch outputs. New actuals/SEC/guidance/price/Leadership-v2 production extraction remains outside this slice; normalized observation inputs support these classes. No current vendor collection, authenticated producer, full native A0 invocation, substantive A3 revaluation, admitted Registry/A5 consumption, mandatory CI, independent A6 or economic validation was executed here.

A successor must retain the original #450 C1/#576 dependency ZIPs and avoid installing dependency_fixture over real native modules. Separate H1 source/impact integration from H2 calibrated forecasting/ranking/policy experiments. No added weights, thresholds, holdout changes, approved books, paper/broker writes or protected-gate changes.

`review_intents[].asset_slices` preserves asset-specific work inside one role batch. The aggregate `slices` field is only a summary. Same-time conflicts compare UTC instants, not textual timezone representations.
