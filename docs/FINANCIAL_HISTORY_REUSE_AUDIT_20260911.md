# 전체 과거 재무 데이터 재사용 조사와 구축안 — 2026-09-11

## 결론과 이번 작업 범위

대상은 미국 상장 주식 전체 후보와 과거 시점의 투자 가능 기업이다. TSM·ASML을 포함한 외국 발행기업도 포함한다. 현재 1,118개 가격 분석 후보는 출발점일 뿐, 전 미국 상장종목이나 과거 투자 가능 종목의 완전한 목록은 아니다.

기존 저장소에는 전 기업 SEC 일괄 자료, 분기별 재무 자료, CIK 매핑, 공시별 접수시각 결합, 변경 기업만 재수집하는 기능이 이미 있다. 새 두 종목 수집기를 확장하는 것보다 이 기능을 선별하여 연결하는 것이 효율적이다. 다만 기존 파생 재무 패널을 그대로 과거 투자 판단에 사용하는 것은 부적절하다. 아래 반례와 버전·통화·자료 범위 문제를 먼저 해결해야 한다.

이번 산출물은 코드/브랜치 조사, 두 가지 오프라인 반례 재현, 구체적인 재사용 설계다. 전체 과거 재무 수집 완료, 저장소의 최신 원본 바이트 검증, 새로운 운용 백테스트 완료를 주장하지 않는다. 실제 수집이나 거래 워크플로를 실행하지 않았다.

## 2. 기존 종목선별 엔진의 재무 사용 경로

현재 master의 r1000_pipeline.py와 r1000_config.py를 확인했다.

1. 회사별 CIK를 정하고 SEC Companyfacts ZIP/회사 JSON 및 분기별 Financial Statement Data Sets(FSDS)를 읽는다.
2. 주요 재무 태그를 추출하여 단일 분기·TTM·성장률·수익성 등의 fund panel을 만든다.
3. feature_store/fund_panel_latest.parquet에 저장하고, 회사 캐시의 수정시간을 기준으로 오래되거나 없는 기업만 갱신한다.
4. 과거 리밸런싱 행에 CIK별 merge_asof를 수행하고 가격·모멘텀/RS·재무 비율을 결합하여 선별 입력을 만든다.
5. 재무가 부족하면 일부 경로에서 yfinance 분기 자료와 현재 시가총액 근사값을 보완한다.

기본 설정에는 최초 FSDS 60개 분기, 재실행 24개 분기, TTM 최대 2개 분기/잔액 최대 4개 분기 보간 설정이 있다. 원본 ZIP 캐시가 있으면 다시 받지 않을 수 있지만, 너무 많은 과거 파일을 반복 읽을 가능성이 있다. 전체 과거 자료를 한 번 정규화하고 공시 단위로 추가하는 편이 낫다.

merge_asof를 사용한다는 사실만으로 미래 누수가 없어지지는 않는다. 결합 전에 이미 미래 정정값을 선택하거나 현재 시가총액을 과거 행에 채웠다면 잘못된 입력을 시간순으로 붙이는 것에 불과하다. 이 경로가 존재한다는 사실과 과거 특정 실행에 실제로 영향을 주었는지는 별도다. 이번에 과거 수익률 전체를 재검산하지 않았다.

## 3. 확인된 결함

### F001 — 신규 전체 후보 경로가 재무는 두 종목만 수집

PR412의 tools/research_source_connection.py에서 universe_mode=us_listed일 때 SEC 수집 대상은 FOREIGN_REPORTING 사전의 키와 후보군의 교집합이다. 사전에는 TSM과 ASML만 있다.

따라서 1,118개 가격 수집 성공을 전체 재무 수집 진척으로 표현할 수 없다. 공급자가 전체 자료를 제공하지 않아서 생긴 제한이 아니다. 전체 대상 CIK를 산출하고, 일괄 자료와 공시 변경 큐를 연결해야 한다. 단순히 제한을 없애고 PR마다 1,118개 API를 반복 호출하는 수정도 피한다.

### F002 — 미래 정정공시가 과거 단일 분기값을 바꿈: 반례 재현

master의 companyfacts_quarterly_flows는 CIK/항목/회계연도/분기별 최신 accepted 행을 먼저 남기고 누적값을 차감한다.

합성 입력으로 실제 함수를 실행했다:
- Q1 최초 매출 100, 공개 2024-05-01
- Q2 누적 매출 250, 공개 2024-08-01
- Q1 정정 매출 120, 공개 2025-05-01

2024-08-02에 알 수 있던 Q2 매출은 250−100=150이다. 전체 자료를 넣은 기존 함수는 250−120=130을 만들면서 그 행의 accepted는 2024-08-01로 유지했다. 미래 행 추가가 과거 값을 바꾸는 반례가 재현됐다. 실제 기업 수치나 전략 성과를 나타내는 테스트가 아니다.

수정 방향은 먼저 해당 판단 시각까지 공개된 버전만 조회하고, 같은 통화·회계기간·연결범위의 누적값을 차감하는 것이다. 계산값의 available_at은 모든 구성 팩트의 가용시각 이상이어야 한다. 원본과 기존 판단 기록은 덮어쓰지 않는다.

### F003 — FSDS 숫자 날짜와 문맥 처리 문제: 반례 재현

prep_num에 정수형 ddate=20240331을 넣으면 2024-03-31 대신 1970-01-01T00:00:00.020240331이 나왔다. 숫자를 문자열 YYYYMMDD로 명시적으로 변환해야 한다.

같은 함수는 version·segments·coreg를 보존하지 않는다. 현행 FSDS는 이 문맥을 포함하므로 연결/부문/다른 단위의 수치가 섞이지 않게 유지해야 한다. int 날짜 반례와 열 제거 동작을 재현했고, 모든 실제 원본 파일에서 같은 문제가 발생했다고 단정하지 않는다.

두 반례는 [읽기 전용 재현 코드](financial_history_audit_20260911/reproduce_counterexamples.py)로 다시 확인할 수 있다. 저장소 루트에서 pandas/numpy가 설치된 Python으로 실행한다. 원본 함수의 SHA-256이 조사 버전과 다르면 중단한다. 출력의 `FAILURE_REPRODUCTION_SUCCESS`는 결함 재현 성공이며 수정 완료나 백테스트 통과가 아니다.

```bash
python docs/financial_history_audit_20260911/reproduce_counterexamples.py
```

### F004 — 공시 버전·기간·통화와 현재값 보완

- 기존 Companyfacts 추출은 filed 날짜를 accepted로 이름 바꾸고 accession을 파생 행에 남기지 않는다. 공시번호로 Submissions/FSDS SUB의 접수시각과 연결하는 기존 B002 방식을 재사용한다.
- 기본 태그 추출에서 USD 단위가 있으면 다른 통화 배열을 배제한다. 과거 USD 번역본과 최근 현지통화 수치를 섞거나 최근 자료를 놓치지 않도록 원본 통화를 모두 보존한다.
- FSDS의 ddate는 실제 수치의 기간 말일이고 SUB.period는 공시의 대표 보고기간이다. 비교기간 수치를 모두 SUB.period로 대체해서는 안 된다.
- B002는 현재 공시의 대표 기간과 같은 팩트만 남기는 제한이 있다. 전 역사 수집에서는 비교기간과 정정 버전도 보존하고, 사용 여부를 시점 조회에서 결정해야 한다.
- yfinance 현재 자료·현재 시가총액 보완은 과거 판단에서 차단한다. 원본 공시 증거가 있는 재무 기록을 우선한다.
- 분기 값 자체를 전방 채움하여 TTM을 만들지 않는다. 과거에 공개된 유효 재무 상태를 다음 공시까지 보유하는 것과 없는 분기를 만드는 것은 다르다.

### F005 — 자동 업데이트와 저장소가 하나로 연결되지 않음

- free_data_daily_update.yml의 정기 실행은 sec_companyfacts=false다. 이름이 Daily여도 정기 SEC 전체 재무 갱신을 의미하지 않는다.
- fetch_run287_recent_companyfacts.py는 현재 제한된 새 공시 기업용이며 6-K를 포함하지 않는다. 6-K/8-K 전체를 무조건 재무로 취급하지 말고 실제 실적/재무 첨부를 식별해야 한다.
- 과거 P0-4 저장소 조사에는 Companyfacts ZIP과 fund_panel_latest가 변경 가능한 단일 파일로 등록돼 있고 해시로 연결된 불변 원본이 없다고 기록돼 있다. 이는 당시 메타데이터다. 이번에 현재 Drive 파일 상태를 다시 검증하지 않았다.
- 새 수집기는 별도 사설 스냅샷을 사용한다. 기존 bulk/FSDS/공시 인덱스와 새 원본 영수증 사이에 공통 카탈로그가 필요하다.

## 4. 수집 범위와 소스

전체 재무제표의 원본 보존과 선별용 20~40개 지표 추출을 분리한다. 선별에 쓰지 않는 항목도 원본에서 버리지 않는다.

| 계층 | 확보 대상 | 목적 |
|---|---|---|
| 원본 재무제표 | 재무상태표·손익·현금흐름·자본변동·포괄손익, 연간/분기/반기 및 정정공시 | 원래 표의 항목·단위·보고 문맥을 보존 |
| 공시 이력 | CIK·accession·공시 양식·접수시각·보고기간·원문 주소·수집시각·해시 | 과거 시점 재구성과 중복 수집 방지 |
| 주석·사업 설명 | 주석/부문 매출·고객 집중·주식보상·부채 조건·위험·관련자 거래 | 기술·산업·지배구조 분석의 근거 |
| 정규화 재무 | 보고 통화별 분기/반기/연간/TTM, 현금·부채·주식수 등 | 전 후보의 공통 수치 평가 |
| 평가 시점 자료 | 해당 날짜 가격·발행주식/ADS 비율·환율·시장/업종 비교 | 같은 시점의 가치평가와 종목선별 |

SEC API는 기업별 공시 이력과 표준 XBRL 수치를 제공하며 일괄 ZIP도 제공한다. Companyfacts만으로 기업 고유 태그·모든 부문/주석·비XBRL 첨부가 전부 확보되는 것은 아니다. [공식 API 범위](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)

초기 구축:
1. 기존 bulk·FSDS·회사 원본·공시 인덱스·사설 스냅샷을 공통 재고에 등록한다. 실제 바이트 해시와 원본 기간을 확인하고 같은 파일을 중복 다운로드하지 않는다.
2. Companyfacts와 Submissions 일괄 자료를 기준으로 시작한다. 추가 공시 이력 파일도 포함됐는지 확인하고 필요하면 Submissions의 files 목록을 끝까지 따라간다.
3. 기본 재무제표의 전체 항목과 고유 태그·문맥은 FSDS의 SUB/NUM/TAG/PRE를 함께 보존한다. 2016Q1~2026Q2는 42개 분기 묶음이다. 자료가 없는 최신 분기는 공시별 새 수집으로 채운다.
4. 첫 운용 창은 기존 요청인 2019-06-03~최신 완료 미국 종가다. 2016년 이후 자료를 워밍업에 사용하며 더 긴 지표가 필요하면 필요한 이전 원본까지 연장한다. 시작일을 바꾼 연구는 별도 식별한다.
5. 발행기업 원본은 CIK 기준으로 한 번 수집한다. 과거 종목선별은 별도의 상장·폐지·합병·티커 변경 이력과 결합한다. 현재 1,118개만 과거로 소급하지 않는다.

FSDS는 2009년 이후 공시 자료를 분기별로 제공한다. 현재 공개 목록의 최신 묶음은 2026Q2다. 2024년 재처리로 문맥 필드가 추가됐으므로 다운로드 버전과 해시를 보존해야 한다. [공식 FSDS](https://www.sec.gov/data-research/sec-markets-data/financial-statement-data-sets), [표 구조 설명](https://www.sec.gov/files/financial-statement-data-sets.pdf)

주석 자료는 별도 월별 일괄 데이터와 원 공시를 이용할 수 있다. 기본 재무제표 완료율과 주석/정성 근거 완료율을 각각 표시한다. 자료량을 측정해 월 단위로 나누고, 모든 주석이 수집됐다는 선언을 기본 재무제표 완료와 혼동하지 않는다. [SEC 주석 자료](https://www.sec.gov/data-research/sec-markets-data/financial-statement-notes-data-sets)

외국 발행기업:
- 20-F·40-F뿐 아니라 실제 재무가 포함된 6-K/IR 첨부도 처리한다.
- SEC XBRL → 공시 원문 표 → 공식 IR/본국 공시 순으로 보완한다.
- TSM/ASML이라는 티커별 사전으로 전체 수집 범위를 결정하지 않는다.
- 반기 보고 기업에 없는 분기 수치를 만들어 넣지 않는다. 반기/연간 비교와 해당 업종의 사용 가능한 지표로 처리한다.
- 기업 전체 현지통화 수치, 보통주 수, ADR/ADS 비율, 미국 상장 증권 가격을 별도 관리한다.
- 유료 공급자는 무료 경로를 시험한 뒤 정확히 남은 기업·기간·항목의 결측을 채우는 용도로 비교한다. 비용 승인 없이 새 서비스 구매는 하지 않는다.

시점 조회 원칙:
- 과거 분석은 그 판단 시각에 공개된 공시 버전만 조회한다. 오늘 내려받은 원본의 수집일을 공시일로 바꾸지 않는다.
- 공개 시각과 우리 시스템의 수집 시각을 따로 저장한다. 과거 공개자료를 이용한 재구성과 실제 그때 수집한 운영 기록도 구분한다.
- 접수시각의 타임존·공개 지연 정책·장마감 이후 공시 처리를 명시한다. accepted_at이 실제 웹 공개시각과 완전히 같다고 가정하지 않는다.
- 최신 정정값 보기와 당시 알려진 값 보기를 따로 제공한다. 정정공시는 새로운 버전이다.
- Q2=H1−Q1, Q4=FY−9M 등의 차감에는 기간·회계기준·통화·연결범위가 맞는 공개 버전만 사용한다.
- 서로 다른 주식 단위/통화를 섞지 않으며 가용 시각이 불명확한 값은 과거 투자 입력으로 사용하지 않는다.

## 6. 저장과 효율

기존 Drive와 사설 원본 저장을 활용하되 연구용 원본/파생 데이터의 단일 카탈로그를 만든다. 새 클라우드 구축을 기본 전제로 삼지 않는다. 승인 계좌/원장 저장 경로는 별도다.

- 원본은 내용 해시로 중복 제거하여 불변 압축 묶음에 저장한다. 원본·표준화 결과·전략 결과를 구분한다.
- 정규화 수치는 Parquet, 작업 큐/공시 인덱스/스냅샷 헤드는 SQLite 등 작은 색인으로 관리한다. 분석기는 필요한 기간·기업 파티션만 읽는다.
- 파일을 회사×항목별로 수만 개 업로드하지 않는다. 원본별 색인을 유지하되 전송은 공시월/CIK 버킷의 적당한 크기 묶음으로 한다. 실제 데이터로 파일 크기·메모리·전송량을 정한다.
- 매일 전체 ZIP을 다시 내려받지 않는다. 새 공시 번호를 확인한 뒤 변경 기업만 갱신한다.
- 같은 공시를 여러 ADR/보통주 티커 때문에 여러 번 받지 않는다. CIK 단위 수집 후 증권별 평가 시점에 연결한다.
- 공시별 파싱 결과는 raw_hash + parser_version + mapping_version으로 캐시한다. 매핑 규칙을 바꾸면 해당 자료만 재처리한다.
- 한 수집 주체가 쓰고 여러 분석기가 읽게 한다. 파일 저장·검증 후 스냅샷 manifest를 마지막에 게시한다.
- GitHub Actions cache는 속도용, artifact는 전달용이다. 장기 보존의 유일한 근거로 삼지 않는다. Git에는 코드와 작은 카탈로그/검증 결과를 둔다.
- 최신성은 파일 수정시간이 아니라 최신 공시와 해당 기업의 실제 보고주기에서 판단한다.
- Drive 403/429는 오류 종류를 분류하고 지수 백오프 및 재개 큐를 사용한다. 전체 디렉터리 반복 검색을 줄인다. Drive 이용권만으로 API 요청 한도가 사라지는 것은 아니다. 실제 프로젝트 한도는 별도 확인이 필요하다. [Google 공식 한도 설명](https://developers.google.com/workspace/drive/api/guides/limits)

SEC의 현재 최대 요청률은 초당 10건이다. 설계 기본값은 전체 작업을 합쳐 그보다 낮게 제한하고 429/503 등에 백오프를 적용한다. 이는 새 병렬 수집기를 여러 개 띄워 합산 한도를 넘지 않게 하는 규칙이다. [SEC 개발자 안내](https://www.sec.gov/about/webmaster-frequently-asked-questions)

## 7. 업데이트와 종목선별 연결

아래 일정은 설계안이며 이번 조사에서 새로 활성화하지 않았다.

| 시점 | 실행 | 전부 다시 할 필요가 없는 것 |
|---|---|---|
| 초기 1회 | 전체 과거 원본 재고 확인, 부족한 기간 일괄 수집·정규화 | 기존에 검증한 동일 원본 다운로드 |
| 미국 공시일 매일 | 새 공시/정정 번호 → 해당 CIK 재무/첨부 추가 → 영향 받은 파생값 재계산 | 미변경 기업의 재무 파싱 |
| 미국 장 종료 후 | 가격·RS·가치평가 갱신, 전 후보 공통 평가, 보유종목 재검토 | 전 기업 공시 원문 재수집 |
| 주간 | 누락/실패 큐·외국기업 IR·신규상장 연결 점검, 카탈로그 복구 검사 | 과거 성공 작업 전체 |
| 분기 자료 게시 시 | 새 FSDS 분기 수집, 공시별 갱신과 대조·누락 보충 | 2016년 이후 모든 ZIP 재파싱 |
| 매핑/전략 변경 시 | 영향 범위 파생자료 재생성, 동일 데이터로 비교 평가 | 원본 재수집 |

공시 수집은 가격 수집 실패나 과거 원장 승인 문제 때문에 중단되지 않게 한다. 가격/재무/거시 수집이 각각 진행되고, 투자 입력을 만드는 시점에서 필요한 완전성을 검사한다.

종목선별은 전 후보 공통 재무 평가를 거친다. 매출·이익·마진·현금흐름·재무건전성·희석·수익성과 RS·가격 기대치를 결합하되 업종별 의미가 다른 항목은 구분한다. 은행의 부채나 REIT의 회계이익을 일반 제조업과 같은 기준으로 감점하지 않는다.

자료 수집 대상 전체와 심층 정성 검토 우선순위는 별개다. 보유종목과 상위/급변 후보의 기술·산업·지배구조 원문 검토를 우선할 수 있지만, 그 이유로 나머지 기업의 기본 재무 수집을 생략하지 않는다. 과거 정성평가에는 당시 공개된 근거만 쓰며, 현재의 기업 판단을 과거에 덧씌우지 않는다. 정성 입력이 없는 숫자 기반 비교 연구는 전체 통합 전략과 별도로 표시한다.

단기 운용 구간은 완주 가능성과 회계/자료 연결을 확인하기 위한 사전 검증이다. 수익률을 보고 유리한 기간이나 규칙을 고르지 않는다. 전체 백테스트는 과거 유니버스/가격/기업행동 등 필요한 게이트를 통과한 뒤 실행한다.

커버리지는 최소 다음을 따로 보고한다:
- 요청/식별/원본 보유/공시시각 연결/정규화/TTM/가치평가/투자 입력 승인 기업 수
- 기업별·연도별·분기별, 미국/외국 발행기업별, 업종별
- 원본 재무제표 5종과 주석의 범위, 필드별 결측 사유
- 신규상장 이전 또는 실제 미공시 반기는 적용불가로 구분하되 이 때문에 다른 결측을 숨기지 않음
- 파일 보유율·요청 기록률·실제 재무 사용 가능률을 같은 100% 수치로 합치지 않음

백테스트 결과를 이어 붙이는 최적화는 나중이다. PR411도 전체 계좌 상태 체크포인트의 검증된 재개를 구현했다고 주장하지 않는다. 원본/전처리는 증분 처리하되 전략 운용 재생은 우선 전 기간을 동일 입력으로 재현한다. 새 데이터가 없으면 동일 결과를 검증하여 재사용하고, 새 전략 이름으로 이미 본 기간을 새 표본외 기간으로 취급하지 않는다.

## 9. 우선 수정 대상

1. research_source_connection.py의 두 종목 제한을 전체 CIK 작업 계획으로 교체하고, 기존 bulk/FSDS/공시 인덱스 어댑터에 연결.

5. 공통 커버리지 파일을 현재 평가기와 과거 재생기가 함께 읽게 하고, 단계 3의 실제 운용 연결부터 확인.

이번 요청은 이전 구현 조사와 효율적인 구축 아이디어 수립이다. 위 수정·전체 재무 수집·전략 실행을 이미 완료한 것으로 보고하지 않는다.
